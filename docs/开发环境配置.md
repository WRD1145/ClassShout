### 现在直接编译 Android 会报什么错（实测）

```
error NETSDK1147: 要构建此项目，必须安装以下工作负载: android
```

**原因**：Android 的 SDK 包文件确实躺在磁盘上，但 .NET 的「工作负载安装记录」是空的，
所以 SDK 不认账。这不是缺文件，是**缺注册**——补一条命令即可，不用重下几个 G。

## 二、目标版本矩阵

这套组合是 .NET 10 + Avalonia 11.3.12 当前推荐的搭配：

| 组件 | 版本 | 说明 |
|---|---|---|
| .NET SDK | 10.0.401 | 已满足 |
| `net10.0-android` | → `net10.0-android36.0` | 由工作负载 `Microsoft.Android.Sdk.Windows 36.1.53` 提供 |
| Android Platform | **`android-36`** | 编译目标，必须装 |
| Android Build-Tools | **`36.0.0`** | 必须装 |
| JDK | **17**（最低 17.0） | 建议 Microsoft OpenJDK 17.0.14 |
| Avalonia | 11.3.12 | 与 FluentAvalonia 2.5.1 配对 |

> `android-36` / `build-tools 36.0.0` 这两个版本号是从 `Microsoft.Android.Sdk.Windows\36.1.53` 的
> `Xamarin.Installer.Common.targets` 里读出来的默认值，照装即可，别装 35。

## 三、步骤一：安装 .NET Android 工作负载

**必须用「管理员身份」打开的终端**（要写入 `C:\Program Files\dotnet`）。

```powershell
dotnet workload install android
```

完成后验证：

```powershell
dotnet workload list
```

预期能看到类似：

```
已安装的工作负载 ID    清单版本
android               36.1.53/10.0.100
```

> 如果报权限错误，就是没提权；如果报找不到清单，先执行 `dotnet workload update` 再装。
> 这一步只是把磁盘上已有的包「登记」进去，通常几秒钟就结束，不会重新下载几 G。

## 四、步骤二：准备 JDK 17

你原来的 Liberica JDK 18 **高于**最低要求 17，理论上能用；但 Microsoft 的 Android 工具链
对 17 的兼容性验证最充分。

**本机已装好**，无需再操作：

```powershell
winget install Microsoft.OpenJDK.17   # ← 已经装过了
```

实测路径与版本：

```
C:\Program Files\Microsoft\jdk-17.0.20.101-hotspot
openjdk version "17.0.20.1" 2026-08-18 LTS
```

> 注意：JDK 的小版本号会随更新变化，**不要硬编码**。用下面这行自动取，后面的命令都引用它：
>
> ```powershell
> $jdk = (Get-ChildItem "C:\Program Files\Microsoft\jdk-17*" -Directory | Select-Object -First 1).FullName
> $jdk
> ```

## 五、步骤三：安装 Android SDK

Android SDK 建议放**非系统盘**，例如 `D:\Android\Sdk`。

### 方式 A：让 .NET 自动装（最省事，推荐）

⚠️ **前提：必须先完成步骤一**（`dotnet workload install android`）。
`InstallAndroidDependencies` 是 MSBuild **目标**，不是独立命令，两件事必须都满足：

1. 工作负载已装 —— 否则目标根本不存在；
2. 命令里有**项目文件** —— 否则报 `MSB1003: 请指定项目或解决方案文件`。

仓库里已经准备好一个专用的引导项目 `tools\AndroidSdkBootstrap\AndroidSdkBootstrap.csproj`，
它不引用任何 NuGet 包，所以**不需要联网还原**，也不会被 Avalonia 的依赖问题卡住。

在**任何目录**下都能执行：

```powershell
$jdk = (Get-ChildItem "C:\Program Files\Microsoft\jdk-17*" -Directory | Select-Object -First 1).FullName

dotnet build "D:\Deepseek_Harness\ClassShout\tools\AndroidSdkBootstrap\AndroidSdkBootstrap.csproj" `
  -t:InstallAndroidDependencies `
  -f net10.0-android36.0 `
  -p:AndroidSdkDirectory="D:\Android\Sdk" `
  -p:JavaSdkDirectory="$jdk" `
  -p:AcceptAndroidSDKLicenses=True
```

它会自动拉 `platform-tools`、`platforms;android-36`、`build-tools;36.0.0` 并接受许可。

### 方式 B：手动用 cmdline-tools（可控性更好）

1. 从 <https://developer.android.com/studio#command-tools> 下载 **Command line tools only**（Windows 版 zip）。
2. 解压到 `D:\Android\Sdk\cmdline-tools\latest\`，使得 `D:\Android\Sdk\cmdline-tools\latest\bin\sdkmanager.bat` 存在。
3. 执行：

```powershell
$env:JAVA_HOME = "C:\Program Files\Microsoft\jdk-17.0.14.7-hotspot"
$env:ANDROID_HOME = "D:\Android\Sdk"

& "$env:ANDROID_HOME\cmdline-tools\latest\bin\sdkmanager.bat" --sdk_root=$env:ANDROID_HOME --licenses
# 上面这步会让你把所有许可逐个 y 一遍

& "$env:ANDROID_HOME\cmdline-tools\latest\bin\sdkmanager.bat" --sdk_root=$env:ANDROID_HOME `
  "platform-tools" "platforms;android-36" "build-tools;36.0.0"
```

### 可选：装模拟器（想在电脑上跑 Android 再装）

```powershell
& "$env:ANDROID_HOME\cmdline-tools\latest\bin\sdkmanager.bat" --sdk_root=$env:ANDROID_HOME `
  "emulator" "system-images;android-36;google_apis;x86_64"
& "$env:ANDROID_HOME\cmdline-tools\latest\bin\avdmanager.bat" create avd -n classshout -k "system-images;android-36;google_apis;x86_64"
```

真机调试可以跳过，用 `adb` 连手机即可（你已经有 `D:\platform-tools\adb.exe`）。

## 六、步骤四：配置环境变量

在 PowerShell 里执行（写入**用户级**变量，不需要管理员）：

```powershell
# 先自动定位 JDK 17，避免写死小版本号
$jdk = (Get-ChildItem "C:\Program Files\Microsoft\jdk-17*" -Directory | Select-Object -First 1).FullName

[Environment]::SetEnvironmentVariable("ANDROID_HOME", "D:\Android\Sdk", "User")
[Environment]::SetEnvironmentVariable("ANDROID_SDK_ROOT", "D:\Android\Sdk", "User")
[Environment]::SetEnvironmentVariable("JAVA_HOME", $jdk, "User")

# platform-tools 加进 PATH，方便直接用 adb / fastboot
$userPath = [Environment]::GetEnvironmentVariable("Path", "User")
if ($userPath -notlike "*platform-tools*") {
    [Environment]::SetEnvironmentVariable("Path", "$userPath;D:\Android\Sdk\platform-tools", "User")
}
```

**改完必须重开终端**才会生效。

## 九、常见问题

**Q：`MSBUILD : error MSB1003: 请指定项目或解决方案文件`**
A：`InstallAndroidDependencies` 是 MSBuild **目标**，必须挂在某个项目上执行。
不能像普通命令那样在任意目录直接敲。用 `tools\AndroidSdkBootstrap\AndroidSdkBootstrap.csproj`
（已在仓库中备好，不依赖 NuGet），命令见步骤三方式 A。

**Q：`dotnet workload install` 报 `Access to the path ... is denied`**
A：没提权。重开一个「以管理员身份运行」的终端。

**Q：`dotnet workload list` 输出为空**
A：说明还没装成功，见步骤一。注意这一步是**后面所有步骤的前提**，
没装的话 `-t:InstallAndroidDependencies` 会直接报「找不到目标」。

**Q：报 `XA5300: The Android SDK directory could not be found`**
A：`ANDROID_HOME` 没配或没重开终端；也可以直接在项目里用 `-p:AndroidSdkDirectory=D:\Android\Sdk` 显式指定。

**Q：报 `Could not determine the location of the Java SDK`**
A：`JAVA_HOME` 指向了 JDK 18。改用 JDK 17，或用 `-p:JavaSdkDirectory=...` 显式指定。

**Q：想用 10.0.102 等旧 SDK 绕开工作负载？**
A：实测不行，`NETSDK1147` 一样会报——工作负载记录本来就是空的，换 SDK 版本解决不了。

## 十、配置完成后的项目命令速查

```powershell
# ---- 构建 ----

# 全量构建（含 Android，需要本文档前九步都配好）
dotnet build ClassShout.slnx

# 只构建桌面相关（教室端 + 教师端桌面头）—— 不需要 Android SDK
dotnet build ClassShout.DesktopOnly.slnf

# ---- 运行 ----

# 教室端（Windows，含系统 TTS 与音频播放）
dotnet run --project src\ClassShout.Classroom

# 教师端桌面头（手机比例窗口，用于在 PC 上调界面与麦克风）
dotnet run --project src\ClassShout.Teacher.Desktop

# ---- Android ----

# 出 APK（约 63 MB，含 arm64 + x64 两个 ABI）
dotnet build src\ClassShout.Teacher.Android -c Release
# 产物：src\ClassShout.Teacher.Android\bin\Release\net10.0-android36.0\com.classshout.teacher-Signed.apk

# 装到手机
adb install -r src\ClassShout.Teacher.Android\bin\Release\net10.0-android36.0\com.classshout.teacher-Signed.apk

# ---- 自检（改动后跑这两个确认没坏）----

# 端到端联调：发现 → 握手 → 文字 → 语音逐字节校验 → TTS → 断开，共 19 项
# 加 tts 开关会真的用喇叭读一句中文
dotnet run --project tools\ClassShout.EndToEnd -- --tts

# 界面渲染 + 像素级校验，产物在 artifacts\ 下
dotnet run --project tools\ClassShout.DesignPreview -- artifacts
```

> 若 `dotnet run` 报找不到 Android SDK，说明当前终端没继承环境变量 —— 重开一个终端即可。
